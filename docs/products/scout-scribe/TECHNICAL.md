# Scout.Scribe — Technical design

Status: M1 capture experiment implemented with NAudio 3.3.0 and WMF, followed by tray/panel/settings refinements; synthetic verification is recorded, with remaining hardware and reliability acceptance open. No model processing is implemented. The [recording baseline ADR](../../engineering/decisions/0004-scribe-recording-baseline.md), [format/durability successor](../../engineering/decisions/0005-scribe-audio-durability.md) and [capture stack decision](../../engineering/decisions/0006-scribe-default-devices-and-capture-stack.md), with their successors, record accepted requirements. ## Process and project boundary

The implemented projects are `src/Scout.Scribe/Scout.Scribe.csproj` and `tests/Scout.Scribe.Tests/`, targeting the latest generally available Windows 11 x64 only. Stack: .NET 10 Windows Forms/NotifyIcon (`net10.0-windows`, `win-x64`), NAudio 3.3.0/WASAPI capture and Windows Media Foundation encoding. Copy a framework-dependent Debug/Release output folder, requiring .NET 10 Desktop Runtime; building requires the .NET 10 SDK. No installer or publishing pipeline. FFmpeg is not required by this .NET experiment. See the [capture stack decision](../../engineering/decisions/0006-scribe-default-devices-and-capture-stack.md) and its successors.

Resolve the normal Windows system-default microphone at each Start and retain it for that session, with no saved device override or selector. Capture its native format. Under [ADR 0008](../../engineering/decisions/0008-scribe-playback-before-listening-volume.md), playback uses WASAPI application loopback excluding Scribe and its descendants, before endpoint listening-volume processing. This captures application audio across all output devices; it is not filtered to the default render endpoint. The virtual device has no native endpoint mix format, so request 48 kHz stereo float explicitly. Convert both sources independently through WMF into `microphone.mp3` and `playback.mp3`. No mixing, inverse-volume gain, normalization or level controls. LG/AMD hardware measurements and decoded MP3s verify listening-volume independence at 20% and 10%; broader hardware and long-session acceptance remain open.

Consent is external: no Scribe consent prompt or acknowledgment metadata. Drive distinct tray icons from live capture state, start idle after every launch, remove the icon on graceful exit and handle shell re-registration. Windows may retain a stale icon after abrupt process death. Preserve available partial audio and allow explicit restart into a new file; automatic repair, merging and Web-aware reminders are outside M1. Pause is optional.

Register WinForms UI and AppDomain last-chance exception hooks early; handle capture/writer errors at operation boundaries. Manageable failures attempt bounded, idempotent audio shutdown and tray hide/disposal before exiting. Last-chance handlers are minimal best effort and must avoid UI-thread waits or locks that could deadlock. Forced kill, FailFast and catastrophic failures can bypass cleanup, so checkpointed audio must remain usable independently. No external watchdog is included.

Continuously encode/write with bounded buffers and file checkpoints every five seconds on a dedicated writer path away from capture callbacks. Crash-usable committed audio is mandatory: it must decode without Stop, repair or restart. Account for encoder/output buffering without repeatedly finalizing the encoder. Test arbitrary application termination, including after 90 minutes, with timed signals to measure the surviving tail, checkpoint latency and incomplete seek/duration metadata. A five-second timer alone does not guarantee the total lost tail. Power outages, blue screens, OS crashes and hardware recovery are outside M1, with no special infrastructure/tests required. S3 semantics are future work. If the selected WMF path fails the durability gate, report evidence and revise the decision explicitly rather than silently changing encoders or acceptance.

Scribe's configurable recording folder defaults to `<Documents>/Scout.Scribe/recordings/`, with timestamp-named sessions and journals. Preferences are stored separately in `%LOCALAPPDATA%/Scout.Scribe/settings.json`; folder changes affect future sessions only. Opt-in launch at Windows sign-in uses the current user's Run registry key and always starts idle. See [ADR 0009](../../engineering/decisions/0009-scribe-tray-recording-panel.md). No OneDrive dependency or cloud adapter is required. Scribe runs without Web, does not reference `Scout.Web`, open its SQLite database or write its managed assets, and requires no local control server. Scribe and its tests are in the solution; Web remains separately buildable.

## Artifact handoff

| Artifact | Initial compatibility contract |
|---|---|
| Audio — M1 experiment | Separate microphone/playback MP3s, each mono/48 kHz/256 kbps in a unique timestamped session directory. About 115.2 MB/hour or 172.8 MB/90 minutes per file; no routine segmentation. Web imports up to 1 GiB per file (about 9.3 hours); exceptional larger files require manual splitting. Both committed outputs must remain playable after termination; verify checkpoint tail and browser playback. |
| Transcript — M2 | Nonempty strict UTF-8 TXT, at most 5 MiB and 1,000,000 .NET string characters per Web import. Explicit ordered parts or clear oversize handling; no silent truncation. Optional source annotations do not create structured Web provenance. |
| Reviewed extraction — M3 | Separate user-reviewed text result, preserving source and proposed/approved distinctions. Exact export format is decided in the M3 plan. If TXT is intended for Web transcript import, it must meet that import's limits and is treated as an external imported text artifact. |

Default handoff is manual upload, which copies preserved output into Web's managed storage. Web's optional audio links only accept relative paths beneath its own `recordings/` directory; Scribe's arbitrary output path is not directly linkable. User-controlled copying is required for that route. No automatic watcher, API or structured promotion is implied. Independent Scribe output requires independent backup guidance.

## Local processing

M2 chooses a local speech-to-text engine and necessary conversion tools after M1 evidence; whisper.cpp and FFmpeg are candidates. Preserve compressed originals and create processing copies, for example 16 kHz mono 16-bit PCM WAV when required by the chosen engine/build. A single recording can be processed in chunks without splitting the original; evaluate memory, duration limits and timestamp continuity in M2. Include explicit input choice, opt-in post-stop transcription, progress, cancellation/retry, interruption handling, transcript limits and engine/model/settings provenance. Decoder compatibility alone does not establish transcription accuracy after lossy compression.

M3 chooses a local LLM/runtime, with Ollama as a candidate only. Define supported fields, source snapshots/references, long-input strategy, model/hardware requirements, result review and local export. Transcription and LLM interpretation are separate stages. Extraction accepts manually supplied text and cannot require a recording run. No silent promotion to verified facts or overwrite of Web records.

No remote provider is enabled by default or invoked implicitly. Required tools/models must be configured explicitly; their installation and operational requirements belong to implementation plans. The [shared constraints](../scout-web/TECHNICAL.md#5-important-constraints) remain applicable.

## Verification and evolution

M1 must prove real microphone/playback capture in separate files, 90-minute duration/relative timing, device loss, directly playable committed outputs after forced termination with measured lost tail, exception-path tray cleanup, tray state/restart and Web import/playback. Record the tested Windows build, camera/Bluetooth routes and unperformed checks. Processing milestones add focused lifecycle, source-preservation, limit and review checks. The [cycle roadmap](../../cycles/scout-scribe-v1/ROADMAP.md) and [decision record](../../engineering/decisions/0001-product-development-cycles.md) define ownership and history.
